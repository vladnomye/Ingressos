# Módulo 0001

## Requerimentos
- Explicar motivos para ser registrar uma *ADR*.

## Problemas
- Sem documentação até mesmo o próprio dev que criou o código pode demorar horas para entender uma função/rotina, 
o registro de decisões evitaria esse problema, se cada função/decisão é documentada, se torna simples entende-lo
mesmo anos após a criação do mesmo.  

## Decisões
- Criar uma pasta de documentações, e a cada biblioteca, função, decisão tomada, registrar um ADR para que no futuro,
minha aplicação possa ser entendível p/ qualquer um que queira usa-la/estuda-la.

## Observações
- Como visto em diversos projetos, uma documentação não é requerimento para se criar uma aplicação, os tão temidos
projetos 'legados' são a prova disso, se cada variável fosse descritiva e cada função estivesse documentada,
mesmo um código 'ruim' que a primeira vista parece incompreensível, torna-se entendível, desde o motivo do uso
do mesmo, até mesmo alternativas descartadas que no fim levaram o dev á usar determinado framework.
Conclui-se portanto, que para a criação de um projeto organizado e de fácil compreensão, registrar decisões
em uma documentação é imprescindível.
